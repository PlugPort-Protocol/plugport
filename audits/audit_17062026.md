# PlugPort v3 — Full Project Audit

Audit scope: all commits on `v3` branch until the commit `00d5af4d20f7a288e46d01302ec3be3ad5d9126c` inclusive of the commit, all packages, contracts, deploy configs, CI, and documentation.

## 🔴 Critical — Security

### S1. JWT Secret regenerates on every server restart
[siwe-handler.ts:L40](file:///Users/shankarwarang/Downloads/PlugPort%20v3/plugport/packages/server/src/auth/siwe-handler.ts#L40)

```typescript
const secret = options?.jwtSecret || randomBytes(32).toString('hex');
```

**Problem:** When no `jwtSecret` option is provided (and it never is — `createHttpServer` passes `options.jwtSecret` which is always `undefined` from `main()`), a random 32-byte secret is generated. Every server restart invalidates **all existing JWTs**, force-logging out every dashboard user.

**Fix:** Add a `JWT_SECRET` env var to `.env.example` and wire it through `getConfig()` → `createHttpServer()`. For dev mode, auto-generate and persist to a file.

### S2. `count` and `distinct` endpoints bypass access control
[http-server.ts:L440-L474](file:///Users/shankarwarang/Downloads/PlugPort%20v3/plugport/packages/server/src/http-server.ts#L440-L474)

```typescript
app.post('/api/v1/collections/:name/count', async (req, reply) => {
    try {  // ← No checkAccess() call!
        const { filter = {} } = req.body || {};
        const count = await store.countDocuments(req.params.name, filter);
```

Both `/count` and `/distinct` skip the `checkAccess(req, reply, collection, 'read')` check that every other collection endpoint uses. An unauthenticated user can count documents and extract distinct field values from **private** collections.

### S3. `user/:address/collections` and `user/:address/metrics` have no auth check
[http-server.ts:L932-L980](file:///Users/shankarwarang/Downloads/PlugPort%20v3/plugport/packages/server/src/http-server.ts#L932-L980)

Anyone can query `/api/v1/user/0xABC/collections` or `/api/v1/user/0xABC/metrics` to enumerate another user's collections, document counts, API key counts, and total request volumes. These should verify `req.user?.address === req.params.address`.

### S4. `deploy/register` allows arbitrary owner spoofing
[http-server.ts:L993](file:///Users/shankarwarang/Downloads/PlugPort%20v3/plugport/packages/server/src/http-server.ts#L993)

```typescript
ownerAddress: (ownerAddress || req.user.address).toLowerCase(),
```

The caller can pass an arbitrary `ownerAddress` in the body, registering contracts under someone else's account. Should always use `req.user.address`.

---

### S5. Gas Station balance endpoint is unauthenticated and unvalidated
[http-server.ts:L1032-L1074](file:///Users/shankarwarang/Downloads/PlugPort%20v3/plugport/packages/server/src/http-server.ts#L1032-L1074)

`/api/v1/deploy/gas-station/:address/balance` accepts any address with no validation. An attacker could:
- Enumerate wallet balances of arbitrary addresses
- Use the server as a free RPC proxy

Should at minimum validate the address format and rate-limit aggressively.

---

### S6. Privacy mode change doesn't require ownership
[http-server.ts:L883-L896](file:///Users/shankarwarang/Downloads/PlugPort%20v3/plugport/packages/server/src/http-server.ts#L883-L896)

Any authenticated user can flip any collection from `public` → `private` (or vice versa). The endpoint checks `req.user?.address` exists but doesn't verify the caller is the collection owner.

## 🟠 High — Bugs

### B1. CSS: Spacing/Radius/Transition tokens only defined inside `[data-theme='dark']`
[globals.css:L70-L83](file:///Users/shankarwarang/Downloads/PlugPort%20v3/plugport/packages/dashboard/src/app/globals.css#L70-L83)

```css
[data-theme='dark'] {
  /* ... dark overrides ... */
  --sidebar-width: 260px;    /* ← Only defined here! */
  --radius-sm: 6px;
  --transition-fast: 150ms cubic-bezier(0.4, 0, 0.2, 1);
  /* etc. */
}
```

These layout/motion tokens (`--sidebar-width`, `--radius-sm`, `--radius-md`, `--radius-lg`, `--radius-xl`, `--transition-fast`, `--transition-base`, `--transition-slow`) are **only defined in the dark theme block**, not in `:root`. In light mode, every component referencing `var(--radius-sm)` or `var(--transition-fast)` will get an empty value — **layout and animations are completely broken in light mode**.

### B3. `InMemoryKVStore` doesn't implement `batchWrite()`
[kv-adapter.ts](file:///Users/shankarwarang/Downloads/PlugPort%20v3/plugport/packages/server/src/storage/kv-adapter.ts)

The `KVAdapter` interface marks `batchWrite` as optional, and `InMemoryKVStore` simply doesn't implement it. When `RoutingAdapter.batchWrite()` checks `this.publicAdapter.batchWrite` (line 149), it's `undefined` for in-memory stores, silently dropping all writes during batch operations in dev mode.

## 🔵 Low — Testing & Quality

### T1. Missing access-control tests for `count`, `distinct`, `user/` endpoints
No integration tests verify that private collections reject unauthenticated `count`/`distinct` requests, or that `user/:address` endpoints are scoped.

### T2. No tests for `RoutingAdapter` routing logic
The `RoutingAdapter` has zero test coverage. Routing decisions (metadata → public, `col:` → privacy check) are untested.

### T3. No tests for dark mode CSS correctness
Light mode is fundamentally broken (B1) and there are no visual regression tests.

### T4. `InMemoryKVStore` `batchWrite` gap has no test
Should test that batch operations work end-to-end in dev mode.
